Root cause

Shipped 1.5.0.0 source (kurupted/CS2TransitView TransitUISystem.cs:1137):

if (HasComponent<Building>(owner) && HasComponent<PrefabRef>(owner))
{
    var pRef = GetComponentData<PrefabRef>(owner);
    var ownerPrefab = prefabSystem.GetPrefab<PrefabBase>(pRef); // throws
}

On load, ResolvePrefabsSystem sets m_Index = -1 - n for every save prefab this boot did not register, then logs Unknown prefab ID. GetPrefab is m_Prefabs[m_Index] with no check. TryGetPrefab rejects m_Index < 0.

This boot’s unknown transit IDs: ContentPrefab:Mod:81040, W7MiniBusStation, W7EU_BusStop02 (GUID 28dd14c3…). That is More Transport (OLD). Playset has More Transport (NEW) 150791 instead. BTV has no MissedDependencies on 81040.

Same unknown IDs on 2026-08-16 sessions that did not throw: those logs never hit this ActivateTransitMode stack (button-render only). Mode string is always "custom" (source).

Fix

  • Code: replace GetPrefab<PrefabBase> at 1137 / 1175 / 1215 with TryGetPrefab; skip to the existing "Bus Stop #n" fallback. Do the same for GetPrefab<TransportLinePrefab> in UpdateTransitLinesData. Upstream main still uses GetPrefab.
  • Playset workaround: enable More Transport (OLD) 81040. NEW 150791 does not register those old IDs. Not a BTV/XTM load-order issue.
